# OWOS Concept Brief Instructions

Use `.codex/skills/continue-owos-concept-brief/SKILL.md` for every Concept Brief intake, research,
design, build, revision, validation, connection, correction, or release task.

Read `core/standards/CONCEPT-BRIEF-PRODUCTION-CONTRACT.md` before working on a package.

The structured package is authoritative. Compiled HTML is delivery output.

Do not:

- treat a supplied source as verified because it already exists;
- promise absolute or eternal factual certainty;
- release with less than 100 percent material-claim verification coverage;
- allow a technical claim to pass without qualified review;
- force the same sections, visuals, interactions, or closing pattern across briefs;
- treat Community discussion as verified instruction;
- treat sponsorship as evidence;
- grant a commercial participant editorial rights;
- publish Graph edges without approval; or
- publish a preview, credential claim, operating recommendation, or release without Hardeep's
  explicit approval.

Run the compiler, portfolio distinctiveness check, rendered reviews, QA report, and release-ready
validation yourself. Report every unresolved source, factual, technical, practitioner, learner,
accessibility, Graph, Community, commercial, and release review.

For public water-sector Concept Briefs, use current federal primary authority and EPA guidance.
Exclude state requirements from public claims, citations, comparisons, Graph evidence, learner
content, review dossiers, and source registers. Route state or permit details to a separately
governed private jurisdiction-specific work product. Exclude non-United States regulations,
standards, government guidance, design guides, operator guides, and health guidelines from the
claim basis, narrative, Graph, review dossier, and source register.
