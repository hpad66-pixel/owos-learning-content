# Instructor Guide

## Teaching stance

Assume the learner knows utility work and is new to agent terminology. Respect existing operational judgment. Explain the technology without implying that professional experience is obsolete.

## Facilitation pattern

1. Begin with the utility situation, not the technical term.
2. Ask for the learner's initial decision.
3. Reveal the mechanism in small observable steps.
4. Ask what could fail and who would notice.
5. Compare operator, manager, data, regulatory, and executive views.
6. Connect the lesson to one capstone field.
7. Close with one practical action.

## Common misconceptions

| Misconception | Plain-English correction |
| --- | --- |
| Every chatbot is an agent | Chat is an interface. An agent directs work and uses approved tools toward a goal. |
| Retrieval makes a system an agent | Retrieval finds context. It does not automatically plan or act. |
| More agents means a better system | More agents add handoffs, cost, delay, and new failure points. Use them only when specialization earns the complexity. |
| Agentic means fully autonomous | Agentic behavior exists on a spectrum and can remain tightly bounded. |
| Guardrails are one safety filter | Safe design uses several controls, including permissions, identity, checks, monitoring, limits, and human authority. |
| A good answer proves success | The final state and real outcome must be checked. |
| A capable model fixes poor data | The model cannot create trustworthy evidence from missing or conflicting records. |
| The agent owns the decision | A named person or authorized body remains accountable for consequential utility decisions. |

## Role lenses

- Operator: usefulness, clarity, field reality, interruption, and safe escalation
- Maintenance leader: work preparation, evidence quality, backlog, and handoff
- Utility manager: authority, consequence, performance, and change management
- Regulatory or water-quality professional: provenance, evidence, review, and certification boundary
- Data leader: sources, identity, permissions, quality, state, and evaluation
- Capital-program manager: workflow coordination, submissions, risk, schedule, and decision records
- Executive: value, accountability, cyber risk, operating model, and investment boundary

## Discussion prompts

- What part of this work must remain human, and why?
- What record would you need before trusting this recommendation?
- What is the simplest architecture that could perform the job?
- Which permission would you refuse during the first pilot?
- What failure would be hard to notice?
- Who owns the outcome when three agents and two departments contribute?

## Review boundary

The instructor does not approve production deployment. Capstone feedback focuses on clarity, boundaries, evidence, measurement, and decision ownership.
