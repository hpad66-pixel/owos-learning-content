# Module 5 Design Brief: Agent, Agentic, or Automated?

Status: learner-facing master-class candidate built

## Learning job

Four vendors describe four different products as agents. The learner must determine what each system actually does and whether added autonomy is useful.

## Outcomes

The learner can place a system on an autonomy spectrum, distinguish an agent from an agentic architecture, compare fixed and adaptive control, account for consequence, and recommend the simplest suitable architecture.

## Experience design

| Element | Design |
| --- | --- |
| Narrative | Vendor claim review and architecture decision studio |
| Mental model | Autonomy and consequence are separate dimensions |
| Visuals | Spectrum, 2x2 consequence matrix, decision tree, cost-latency bars, architecture cards |
| Interaction 1 | Place utility scenarios on the autonomy spectrum |
| Interaction 2 | Simplest-solution recommender with transparent rules |
| Quiz mix | Classify, true or false, reflection |
| Work product | Autonomy and Consequence Decision Record |
| Capstone | Select and justify the least complicated architecture |
| Graph | Architecture types connect to properties, controls, risks, and suitable tasks |
| Mobile | Drag interaction becomes tap-select with an accessible placement list |

## Completion evidence

Scenario placements completed, recommendation challenged, knowledge check passed, and decision record saved.
