# Module 7 Design Brief: Where Utilities May Become Agentic

Status: curriculum build

## Learning job

Seven utility teams propose agent ideas. The learner must identify value, readiness, consequence, evidence, cost, and whether a simpler solution is preferable.

## Outcomes

The learner can recognize bounded use cases, compare value and risk, distinguish information technology from operational technology, identify readiness gaps, and reject an agent proposal when it is unnecessary or unsafe.

## Experience design

| Element | Design |
| --- | --- |
| Narrative | Utility opportunity portfolio review |
| Mental model | Value must be considered with readiness and consequence |
| Visuals | Service-area map, opportunity matrix, value-risk plot, role cards, readiness radar, portfolio bars |
| Interaction 1 | Filter use cases by water, wastewater, stormwater, role, and function |
| Interaction 2 | Prioritize or reject proposals using transparent criteria |
| Quiz mix | Classify, estimate, reflection |
| Work product | Utility Agent Opportunity Portfolio |
| Capstone | Compare value, readiness, consequence, cost, and measurement |
| Graph | Use cases connect to assets, processes, roles, competencies, sources, and controls |
| Mobile | Map becomes sector and function filters above ranked cards |

## Use-case families

Regulatory research, work-order preparation, capital-submission review, storm-event information coordination, inspection reconciliation, approved-policy customer service, asset-risk review, and workforce knowledge continuity.

## Completion evidence

Portfolio triage completed, at least one idea rejected with reason, one idea advanced with boundary, and capstone comparison saved.
