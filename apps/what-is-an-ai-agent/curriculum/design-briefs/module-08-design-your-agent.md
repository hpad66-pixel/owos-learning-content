# Module 8 Design Brief: Design Your First Utility Agent

Status: curriculum build

## Learning job

The learner converts one real utility problem into a bounded, testable pilot and defends why an agent is or is not the right architecture.

## Outcomes

The learner can complete a Utility Agent Canvas, define outcome-based evaluations, set cost and usage limits, identify a human owner, create stop conditions, and produce a 90-Day Pilot Brief.

## Experience design

| Element | Design |
| --- | --- |
| Narrative | Guided design, challenge, revision, and defense |
| Mental model | A pilot is a testable operating contract, not a product wish list |
| Visuals | Agent canvas, evidence chain, pilot roadmap, readiness dashboard, evaluation scorecard, decision gate |
| Interaction 1 | Progressive canvas builder using saved work from Modules 1 through 7 |
| Interaction 2 | Adversarial review that tests ambiguity, missing evidence, excessive permissions, weak evaluations, and absent ownership |
| Quiz mix | Checklist, multiple choice, reflection |
| Work product | Utility Agent Canvas and 90-Day Pilot Brief |
| Capstone | Assemble, challenge, revise, and defend the pilot |
| Graph | Learner design previews as a graph of goal, sources, tools, controls, roles, evaluations, and competencies |
| Mobile | Two-pane builder becomes Draft, Review, Graph, and Export tabs |

## Evaluation design

The learner defines historical test cases, expected outcomes, prohibited outcomes, source-coverage checks, tool and permission checks, latency and cost measures, escalation tests, and human review. The course distinguishes a good written response from a correct final state.

## Completion evidence

All required canvas fields, review findings resolved or accepted, pilot brief generated, architecture defended, and learner attestation recorded.
