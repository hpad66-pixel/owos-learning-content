# Module 8 Video Script: Design Your First Utility Agent

Intended length: 8 to 10 minutes

Status: working recording draft

## Spoken words

This final lesson brings every prior decision into one pilot design. You will complete the Utility Agent Canvas and turn it into a 90-Day Pilot Brief.

[Show the canvas filling from the prior seven modules.]

Start with the problem and the user. State the goal in measurable language. Name the approved sources and tools. Describe the actions the system may take. Identify the human owner. Set permissions and prohibited actions. Record the evidence that must support the result. Add evaluation measures, retry limits, stop conditions, and the escalation path.

The canvas is not a technical drawing. It is a shared decision record. Operations, data, security, legal, procurement, program staff, and leadership should be able to read it and see where their review is needed.

[Show the adversarial review.]

Next, challenge your own design. What could fail without being obvious? What source might be stale? What identity could be misused? Which action has too much consequence? What evidence would an approver need? Could a rule or fixed workflow perform part of the job more clearly?

Then build the pilot brief. Keep the first 90 days narrow. Name the users, test cases, owners, measures, review schedule, cost boundary, and stop conditions. A useful pilot is allowed to conclude that the application should not advance.

Your final defense should explain the utility value, the selected architecture, the evidence boundary, the human authority, and the conditions that would cause you to pause or stop.

The course closes with a practical standard. Do not ask whether an agent sounds intelligent. Ask whether the work is observable, supported, bounded, measurable, and owned.
