Isolated records

Everything is available, but the answer is missing

Operations asks, “Which critical-facility accounts could be affected if Pump P-104 is unavailable, and which current procedure applies?” The control system knows the pump event. The geographic system knows pressure zones and premises. The customer system knows accounts and customer classes. The document library holds procedures. No single system owns the complete answer.

A database join can answer a known question when the keys and tables are already understood. A utility knowledge graph makes those relationships explicit and reusable across questions. It does not eliminate source systems or the need for good keys.

Think of the graph as a set of sentences that can connect into paths.

Keep source groups, identifiers, graph names, mappings, and effective time visible so paths remain testable.

Choose questions where relationships cross systems and carry operational value. Do not fund an enterprise graph without a bounded decision.

Find the missing edge

Choose the relationship that turns separate source records into a usable exposure path. Then read the estate map by physical, operational, enterprise, authority, and decision layers. Notice that the graph connects sources without pretending they are one system.

Graph construction

Add only the relationships the question needs

A graph contains nodes and directed, labelled edges. In RDF, each edge corresponds to a predicate in a triple. A path is a sequence of edges. The RDF dataset is the machine-readable content. A graph visualization is one view of that content.

Begin with Pump P-104. Add the zone only when you have an approved asset-to-zone mapping. Add premises through the geographic containment relationship. Add accounts through the service relationship. Add the critical-facility class through a governed customer classification. Add Procedure PR-7 only after checking its effective date and jurisdiction.

A named graph can preserve the source or review context of a group of triples. That matters when GIS, customer, operational, and policy statements have different owners and refresh cycles.

Grow, do not dump

The picture begins with isolated cards. Add one relationship at a time. The answer status changes only when the required path exists. Read the explanation after each addition because a connected graph is not automatically a trustworthy graph.

Separate a supported connection from a causal claim

The graph can support “Account 901 is connected to a premise in Zone 3 served by Pump P-104.” It cannot support “Pump P-104 caused Account 901 to lose pressure” unless the graph also contains the observations, time alignment, hydraulic evidence, and approved rule needed for that conclusion.

This distinction is why graph answers need an evidence path. A visible path helps the reviewer see what the answer says and what it does not say.

Choose the bounded answer

Compare the two statements. One follows the relationships you built. The other adds causation that the graph does not contain. Select the claim the current graph can defend.

Document a Utility Mini-Graph

Your mini-graph should begin with one question and the smallest set of entities and relationships needed to answer it. Record the source group for each relationship, one path test, and one claim the graph must not make.

Write the graph before drawing it

Name the operational question, three to five triple patterns, their source groups, and the answer boundary. The final check rewards a testable path, not a visually impressive node count.

Graph FAQ

Questions about connecting triples

Does every utility relationship belong in one graph?

No. Model relationships that support governed questions and reuse. Separate source, security, jurisdiction, and lifecycle boundaries when they matter.

Is a graph database automatically a knowledge graph?

No. A graph database stores nodes and edges. A knowledge graph also needs governed identity, shared meaning, provenance, constraints, and operating ownership.

How large can an RDF graph become?

Very large graphs are possible, but size is not the first design goal. Start with the smallest graph that answers a valuable question and can be governed.

Can the graph stay connected to live source systems?

Yes. Some relationships can be virtualized or queried through mappings while selected paths are cached or materialized. Later modules compare those access patterns.

Why show the answer path?

The path lets an operator, steward, or leader inspect which records and relationships support the result. It also reveals missing evidence and unsupported leaps.

Evidence boundary

The exposure graph is instructional. It demonstrates RDF paths, not hydraulic causation or emergency authority.
