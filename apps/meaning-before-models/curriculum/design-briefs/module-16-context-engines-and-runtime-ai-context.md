# Module Design Brief: Context Engines and Runtime AI Context

## Identity

| Field | Decision |
| --- | --- |
| Course and module ID | `owos-course-semantic-data-ai-001`, `mbm001:16` |
| Archetype | Context assembly room |
| Signature mechanism | Remove runtime controls and observe the answer boundary |
| Work product | Runtime AI Context Contract |
| Evidence boundary | Fictional exposure task; no communication or action authority |

## Learning job

The same exposure question is asked by a planner and an operator in different states. Learners must
distinguish durable semantics from runtime coordinates, assemble a complete packet, and configure a
fail-closed gate.

## Concept-to-experience plan

| Idea | Visual | Action | Change | Quiz type |
| --- | --- | --- | --- | --- |
| Same words, different task | `packet-anatomy` | Diagnose missing coordinates | Durable and runtime parts separate | `ambiguity-diagnosis` |
| Context engine is a process | `interactive-process` | Toggle packet elements | Answer or blocked state appears | `context-assembly-simulation` |
| Permission omission propagates | `failure-propagation-chain` | Select stop gate | Unsafe transition is interrupted | `fail-closed-gate-selection` |
| Context must be contractual | Artifact preview | Specify task and controls | Callable packet becomes reviewable | `runtime-contract-validation` |

## Module design fingerprint

- Narrative: two-shift question, packet anatomy, live assembly console, permission failure, contract.
- Purposeful interactions: six-control context console and permission stop-gate selection.
- Visuals: `packet-anatomy`, `interactive-process`, `failure-propagation-chain`.
- Assessment sequence: `ambiguity-diagnosis`, `context-assembly-simulation`,
  `fail-closed-gate-selection`, `runtime-contract-validation`.
- Mobile stacks packet and console; dark answer screen uses light text; reduced motion preserves state.

## Instructor explanation plan

Learners inspect what comes from ontology and mappings versus what is supplied only for one run. The
console debrief directs attention to evidence, permission, and risk rather than fluent prose. The
failure chain establishes authorization before action.

## Written-first review

Terms are introduced through the two-shift example: AI context, context engine, ontology, semantic
layer, as-of time, RAG, response schema, and fail-closed control. The lesson states that better context
reduces ambiguity but does not guarantee deterministic or correct generation.

## Visual pacing review

Every explanatory passage is followed by packet anatomy, process flow, live console, chain, gate, or
artifact. No uninterrupted prose exception is used.

## Explanatory graphic plan

Packet anatomy separates durable and runtime knowledge. The process visual separates engine from
packet. The failure chain shows how missing permission survives into an unsafe action.

## Learner FAQ plan

Six questions distinguish ontology from context, context engines from vector search, least-privilege
packets, hallucination limits, workflow state, and role-sensitive context.

## Recording script

Optional only. All required explanation and debrief are written on the page.

## Diversity check

The packet assembly room differs from Module 15's evidence promotion and Module 17's synchronized
pipeline reruns. Its console, packet visual, stop-gate quiz, artifact, and assessment order are unique.
