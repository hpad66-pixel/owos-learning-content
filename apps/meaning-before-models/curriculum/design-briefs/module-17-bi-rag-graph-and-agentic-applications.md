# Module Design Brief: BI, RAG, Graph, and Agentic Applications

## Identity

| Field | Decision |
| --- | --- |
| Course and module ID | `owos-course-semantic-data-ai-001`, `mbm001:17` |
| Archetype | Synchronized pipeline laboratory |
| Signature mechanism | Rerun four pipelines and stop an unsafe agent action |
| Work product | Repeatability and Agent Action Contract |
| Evidence boundary | Fictional overflow case; no live tools |

## Learning job

Learners compose BI, graph, RAG, and agent steps for one overflow investigation. They must identify
fixed and variable steps, rerun the pipelines, and stop an action that lacks approval.

## Concept-to-experience plan

| Idea | Visual | Action | Result | Quiz type |
| --- | --- | --- | --- | --- |
| Different jobs compose | `interactive-process` | Select hybrid architecture | Four lanes align | `architecture-composition` |
| Repeatability is step-specific | `comparison-table` | Rerun all lanes | Fixed results and variable wording separate | `repeatability-simulation` |
| Answer to action is a state transition | `failure-propagation-chain` | Stop at approval | Draft preserved, action blocked | `agent-stop-state` |
| Hybrid behavior needs a contract | Artifact preview | Declare fixed, variable, evidence, action | Pipeline becomes auditable | `pipeline-contract-defense` |

## Module design fingerprint

- Narrative: four questions, repeatability microscope, action state machine, operating contract.
- Purposeful interactions: four-lane rerun log and agent action stop control.
- Visuals: `interactive-process`, `comparison-table`, `failure-propagation-chain`.
- Assessment sequence: `architecture-composition`, `repeatability-simulation`,
  `agent-stop-state`, `pipeline-contract-defense`.
- Dark laboratory screen uses explicit light text and has a mobile single-column mode.

## Instructor explanation plan

The instructor compares full pipelines but labels behavior step by step. The rerun keeps source facts
fixed, varies RAG and planning language, and keeps the action gate fixed. The state-machine debrief
separates evidence grounding from authorization.

## Written-first review

The lesson conversationally defines BI, RAG, graph query, agentic application, approximate retrieval,
sampling, controlled repeatability, decision gate, human approval, and idempotence. It directly
corrects “tables deterministic, RAG nondeterministic, graph deterministic.”

## Visual pacing review

The four-lane map, comparison table, live rerun lab, state machine, stop control, and artifact create
alternating explanation and action. No video is needed.

## Explanatory graphic plan

The lane process separates jobs. The table separates fixed and variable conditions. The state chain
marks the exact point at which software crosses from answer to action.

## Learner FAQ plan

Seven questions cover BI and RAG repeatability, graph hallucination limits, SPARQL fit, agentic
boundaries, human approval, and replay logs.

## Recording script

Optional only. The simulation and all explanations are fully available in HTML.

## Diversity check

Module 16 assembles one context packet. Module 17 reruns four pipelines and uses an action state
machine. Module 18 becomes a review-panel capstone. Openings, interactions, quiz sequence, and work
product are distinct.
