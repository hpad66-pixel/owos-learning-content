# Assessment Blueprint

## Assessment principles

- Assess distinctions the course depends on, not acronym recall alone.
- Use explanatory feedback for every selected response.
- Score syntax only when the expected result is unambiguous.
- Use rubrics for architecture, governance, and operational judgment.
- Make “unknown” an intentional answer when evidence is absent.
- Never reward an unsafe agent action because the predicted outcome sounds useful.

## Final scenario assessment

The learner receives a fictional stormwater scenario containing data models, a taxonomy fragment,
ontology terms, semantic mappings, GIS assets, inspections, rainfall observations, a permit
condition, a staff note, a retrieved passage, an extracted claim, runtime context, and a proposed
agent action.

The learner must:

1. Select or repair six triples.
2. resolve one identity collision;
3. interpret one SPARQL result;
4. identify one valid inference and one unsupported leap;
5. read one SHACL violation;
6. select the currently effective approved statement;
7. choose a justified virtual or materialized access pattern;
8. assemble the required AI context;
9. explain which parts of the answer path are repeatable;
10. stop an unauthorized action; and
11. cite the evidence path used for the final recommendation.

Passing threshold: 80 percent overall and all safety-critical agent decisions correct.

## Pilot requirements before release

- Verify every deterministic answer has one intended outcome.
- Test distractors with nontechnical utility staff.
- Confirm Foundation wording does not depend on hidden Practitioner detail.
- Test graph alternatives with keyboard and screen reader.
- Review all inference, SHACL, authority, and agent-action answers with subject matter experts.
