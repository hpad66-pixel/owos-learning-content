A table join can combine rows when keys and conditions match. It does not decide that three fields named status have the same meaning. In this case they do not. Mapping all three to one generic util:status would create a convenient graph and a misleading one.

Foundation lens: Mapping is the bridge between a source field and a shared concept. The bridge must preserve what the source field actually means.

Practitioner lens: Define subject templates, class assertions, predicate-object maps, joins, term types, datatypes, transformations, graph names, provenance, and tests.

Leader lens: Make mappings governed products with domain approval, source ownership, versioning, tests, and change impact. A mapping error can spread confidently across every consumer.

Reject the shortcut

Choose the approach that preserves three meanings while still connecting them to the same pump, tag, and work order. The shared label is evidence for investigation, not evidence of equivalence.

1
Mapping vocabulary

A mapping tells a processor how source records become RDF terms and triples

A semantic mapping can turn one source row into several triples. A logical table supplies rows. A triples map says how those rows generate graph statements.

A subject map might turn ASSET_ID=P104 into https://utility.example/assets/P104. A predicate-object map might produce rdf:type util:Pump and util:assetLifecycleStatus util:Active.

An IRI identifies a resource. A literal represents a value. A join condition can connect a pump to a pressure zone. A transformation can convert a code to an IRI or normalize a unit.

W3C R2RML is one standard for customized mappings from relational databases to RDF. Other technologies map APIs, event streams, files, and documents. The architecture matters more than the syntax: stable identity, explicit meaning, traceable transformation, and testable output.

Mapping is a claim: “This row represents that pump” and “this code means Active” are semantic assertions. They need evidence, ownership, tests, and version history just like other governed claims.

Value normalization

A number without unit, method, and time is weak knowledge

Historian A reports pressure in pounds per square inch. A hydraulic model reports kilopascals. A dashboard joins the values and displays one trend. If mapping preserves only the number, the graph may compare 105 with 724 as though they used the same unit.

Normalization can help, but preserve the original observation, unit, method, time, and transformation. A converted value is derived evidence. It should not overwrite the source value that allows audit and recalculation.

Wiring FAQ

Questions about mapping enterprise data

Is semantic mapping just renaming columns?

No. It establishes resource identity, class membership, property meaning, relationships, datatypes, code translations, provenance, and graph boundaries. Renaming may be one small presentation step.

Can we map two source records to the same RDF resource?

Yes, when governed identity rules support that conclusion. Preserve links to the individual source records and the reconciliation method so a reviewer can challenge or reverse the match.

Should every source column become a triple?

No. Map what serves the use case and governance need. Some columns are technical artifacts, duplicated labels, or sensitive data. Unmapped columns remain in the source and can be added later through controlled change.

How are documents mapped?

Selected entities, clauses, references, and relationships can be extracted and connected to ontology concepts. Preserve the document, section location, extraction method, confidence, reviewer, and effective status. Do not treat extracted text as automatically authoritative.

Who approves a code translation?

The domain owner and source owner should confirm the code’s business meaning. The mapping steward implements and tests it. A codebook is evidence, but operational exceptions and historical changes may still require review.

When should mappings be virtual instead of materialized?

Virtual mappings reduce copying and can reflect current source values. Materialization may support latency, resilience, history, or expensive transformations. Choose per workload and keep the same semantic and provenance controls.

Evidence boundary

The P-104 codes, identifiers, and unit conversion are instructional. Actual source dictionaries, identifier quality, unit standards, join behavior, access controls, and expected graph outputs require local review. R2RML standardizes relational-to-RDF mappings; it does not decide your utility’s domain meaning or source authority.
