# Module FAQ Blueprint

These are design questions, not final learner-facing answers. Each module's final FAQ must be written
from the completed lesson and utility scenario.

| Module | Questions the FAQ must answer |
| --- | --- |
| 01 | Is RDF a database? Is the diagram the graph? Why not use a spreadsheet? |
| 02 | Can an object be a number? Can a triple have more than three parts? Why are identifiers long? |
| 03 | Why not trust the asset tag? What if systems disagree? Who approves identity? |
| 04 | Does everything belong in one graph? Is every graph database a knowledge graph? |
| 05 | Is a semantic layer an ontology? Is a prompt context? Is a taxonomy enough? |
| 06 | Can one thing have several classes? Who owns definitions? Does RDFS validate? |
| 07 | Can an ontology be wrong? How much should we model? Should we reuse standards? |
| 08 | Is SPARQL harder than SQL? Does it infer? Can it query remote data? |
| 09 | Is inference prediction? What does unknown mean? When is equivalence dangerous? |
| 10 | Why can valid data be wrong? Is SHACL a database constraint? Who handles violations? |
| 11 | Is source the same as authority? Can conflicts remain? How does supersession work? |
| 12 | Is the Knowledge Spine one product? Where does the ontology run? Must all data become RDF? |
| 13 | Is mapping copying? What happens when a column changes? Where are mappings governed? |
| 14 | Is duplication always bad? What if the source is down? Are indexes copies? |
| 15 | Does an embedding contain meaning? Should every sentence become a triple? How are claims cited? |
| 16 | Is a long prompt good context? Does a context window store knowledge? Does good context guarantee consistency? |
| 17 | Does a graph replace RAG? Why can wording vary? Can a correct agent act automatically? |
| 18 | Where should a utility begin? How much graph is enough? What should 90 days produce? |
