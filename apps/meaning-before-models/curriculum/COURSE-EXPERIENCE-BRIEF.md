# Course Experience Brief: Meaning Before Models

Status: approved retrofit direction, implementation required

## Course identity

| Decision | Course-specific answer |
| --- | --- |
| Central argument | Machines do not receive enterprise meaning automatically. Utilities must make identity, relationships, rules, evidence, authority, and context explicit. |
| Learner transformation | Move from seeing RDF as technical syntax to seeing a knowledge graph as a governed way to make utility meaning inspectable and usable. |
| Conversational teaching voice | A patient utility practitioner at a whiteboard, beginning with ordinary questions and revealing the technical language only after the learner understands the job. |
| Utility world | Pump P-104, Zone 3, customer exposure, an overflow response, a stormwater outfall, work orders, procedures, permits, maps, sensor records, operators, stewards, engineers, and leaders. |
| Visual language | Semantic field notebook plus graph laboratory. Real utility assets and records transform into triples, paths, proof traces, validation reports, query results, mappings, and context packets. |
| Information-density rhythm | Short conversational explanation, worked utility example, learner-operated mechanism, plain-English debrief, then transfer to a new water, wastewater, or stormwater case. |
| Signature learning mechanisms | Triple construction, graph growth, identity adjudication, path tracing, query execution, inference proof, shape repair, provenance reconciliation, mapping break test, access-pattern stress test, evidence extraction, context assembly, and agent stop control. |
| Professional artifact family | A connected semantic engineering field book, not eighteen copies of one form. |
| Emotional rhythm | Curiosity, recognition, surprise, construction, skepticism, proof, control, architecture, and confident pilot design. |
| Prohibited motifs | Black graph blobs, generic node clouds, repeated four-step clickers, repeated multiple-choice to matching to multi-select sequences, generic eight-field forms, vocabulary-substitution FAQs, and one five-section page mold. |

## Written-first teaching contract

- Every lesson begins with a question a nontechnical utility professional could ask.
- Technical terms appear only after an ordinary-language explanation and a worked utility example.
- Every graph, query, inference, constraint, or context packet is narrated on the page.
- Each learner-operated mechanism ends with a debrief explaining what changed and why.
- Video may later demonstrate motion, but no required explanation is assigned only to video.

## Shared shell boundary

Keep navigation, accessibility, evidence controls, completion state, Graph, and Community consistent.
Vary section count, layout, simulation, quiz sequence, illustration, density, artifact behavior, and
debrief structure.

## Retrofit decision

The fixed-page generator is retired. All twenty modules use governed structured source and
deterministic compilation. Module 05 remains a capability benchmark, not a page template. Final
release requires the rendered course, distinctiveness, owner approval, and release verification
gates.
