Virtualize, Cache, Index, or Materialize?

The right question is not, “Where should we copy all the data?” It is, “What access behavior does this utility decision require, and what new obligation appears if we create another copy?”

1
Incident clock

The main breaks at 6:12 a.m.

A transmission main has failed. Operations needs a customer exposure list in two seconds. The customer system is authoritative and changes every minute. The geographic information system can be queried, but the network link sometimes drops during storms. The emergency procedure library must remain available even when the document platform is down.

One architecture for all three sources sounds simple. It is also the trap. A virtualized relationship protects source authority, but it inherits source availability and response time. A cache improves speed, but it can become stale. An index makes documents discoverable, but it is not the document itself. A materialized graph can survive an outage, but now you own another copy.

Think of the four patterns as borrow now, keep briefly, make findable, and make a governed copy.

Separate query pushdown, time-to-live, index refresh, and materialized synchronization. Each has a different failure mode.

Every copy creates an owner, refresh promise, security boundary, recovery plan, and cost.

Failure rehearsal

Every performance shortcut creates a truth-management job

A copied customer status can answer quickly and still be wrong. A document index can retrieve the correct paragraph from an obsolete procedure. A virtual query can preserve authority and still fail during an outage. These are not arguments against the patterns. They are reasons to make each boundary explicit.

Questions utility teams usually ask

Is virtualization the same as having no integration?

No. It still needs mappings, credentials, query planning, monitoring, and source availability. It changes when data moves, not whether engineering work exists.

When is a cache safer than a live query?

When a short, declared delay is acceptable and the live source cannot meet the response target. The cache needs an expiry rule and a visible as-of time.

Does a vector index become the authoritative document?

No. It helps retrieve passages. The procedure repository, version, approval, and effective date still establish authority.

When should a utility materialize graph data?

When measured latency, outage, cost, or repeated computation requirements justify a governed copy. Materialize the smallest useful slice and assign its refresh and recovery duties.

Can one question use all four patterns?

Yes. An outage assistant might virtualize customer status, cache a repeated network path, index procedures, and materialize a small offline emergency graph.

What does “move the least data” really mean?

It is a decision principle, not an absolute rule. Keep authority in place when feasible, then copy only what the workload and controls justify.

Evidence boundary

The Riverbend incident is instructional. The stress-test recommendation is a teaching heuristic, not an operational sizing or safety decision. Production choices require measured workloads, source-owner approval, security review, recovery testing, and practitioner review.
