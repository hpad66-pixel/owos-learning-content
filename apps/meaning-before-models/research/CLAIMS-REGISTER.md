# Claims Register

| Claim ID | Proposed claim | Source locator | Status | Limitations | Reviewer |
| --- | --- | --- | --- | --- | --- |
| CLM-001 | The core RDF graph model is a set of subject, predicate, and object triples. | SRC-001, sections 1.1 and 3.1 | verified | RDF 1.2 introduces triple terms, which must be taught only if needed. | Codex initial source check |
| CLM-002 | SPARQL defines query syntax and semantics for RDF graphs. | SRC-002 | verified | The stable SPARQL 1.1 Recommendation must be distinguished from SPARQL 1.2 draft work. | Codex initial source check |
| CLM-003 | OWL is a computational logic-based language that can support consistency checking and inference. | SRC-003 | verified | Reasoning behavior depends on the OWL profile, axioms, and implementation. | Codex initial source check |
| CLM-004 | SHACL describes and validates RDF graphs against shapes and constraints. | SRC-004 | verified | Validation does not prove that a real-world claim is true or that the graph is complete. | Codex initial source check |
| CLM-005 | RDFS provides a data-modeling vocabulary for RDF data. | SRC-005 | verified | The phrase "explains how nodes relate" is useful teaching language but less precise than the specification. | Codex initial source check |
| CLM-006 | Apache Jena provides RDF, SPARQL, inference, ontology, and SHACL capabilities. | SRC-006 | verified | Product capability is not evidence of market adoption. | Codex initial source check |
| CLM-007 | FIBO is a financial-industry ontology developed in OWL and published for machine-readable business meaning. | SRC-007 | verified | FIBO is a finance example, not evidence that the same ontology should be adopted by utilities. | Codex initial source check |
| CLM-008 | Recent interest in Apache Jena, SHACL, and FIBO shows that enterprises are building semantic backbones now. | DIR-001 | unresolved | Requires defined metrics, time period, and adoption evidence. Search interest alone would not establish enterprise implementation. | pending research |
| CLM-009 | SPARQL is built for relationship traversal that the relational model was not designed for. | DIR-001 | supported with limitation | SPARQL is graph-pattern oriented, but relational systems can model and query relationships. Avoid a categorical comparison. | pending technical review |
| CLM-010 | A knowledge graph can provide grounded context to a language model. | DIR-001 | proposed | Must define retrieval, provenance, access control, freshness, and what "grounded" means. A graph alone does not guarantee correctness. | pending research |
| CLM-011 | RDF, RDFS, SPARQL, OWL, and SHACL can be taught as five different jobs around RDF data. | SRC-001 through SRC-005; DIR-002 | supported with limitation | Useful teaching model, but not a mandatory execution sequence or universal product architecture. | pending technical review |
| CLM-012 | Shared subjects and objects allow separate RDF triples to form a connected directed graph. | SRC-001 | verified | The lesson must distinguish shared identifiers from labels that merely look alike. | Codex initial source check |
| CLM-013 | A SPARQL graph-pattern query can demonstrate relationship traversal over RDF data. | SRC-002 | verified | Use one readable example. Do not imply that SPARQL itself performs OWL inference. | Codex initial source check |
| CLM-014 | Power BI model relationships propagate filters between modeled tables according to cardinality and cross-filter direction. | SRC-010 | verified | Power BI carries explicit model semantics. Do not portray it as a meaningless table viewer. | Codex source check |
| CLM-015 | RAG combines parametric language-model memory with retrieved non-parametric memory for generation. | SRC-009 | verified | Modern implementations vary. Teach the core retrieval-plus-generation pattern without claiming one universal architecture. | Codex source check |
| CLM-016 | RAG can generate diverse language, and its answer can change when retrieved passages or generation choices change. | SRC-009; DIR-003 | supported with limitation | RAG is not guaranteed to produce a different answer every run. Fixed retrieval and deterministic decoding can increase repeatability. | Codex source check |
| CLM-017 | An RDF graph application can produce repeatable query or entailment results when data, query, rules, semantics, reasoner, and versions are fixed. | SRC-001 through SRC-005 | supported with limitation | Graph technology alone does not guarantee deterministic end-to-end behavior. A language-model explanation or external tool can still vary. | pending technical review |
| CLM-018 | PROV-O can represent provenance across entities, activities, and responsible agents in different systems and contexts. | SRC-011 | verified | The course uses a small subset and translates the terms into plain language. | Codex source check |
| CLM-019 | A graph-grounded agent can query explicit relationships, validate required structure, propose a tool action, and preserve provenance. | DIR-003; SRC-001 through SRC-005; SRC-011 | proposed architecture | This is a course architecture pattern, not a claim that RDF alone supplies permissions, orchestration, or safe action. | pending architecture review |
| CLM-020 | Under RDF and OWL open-world semantics, absence of a statement does not generally establish that the statement is false. | SRC-001; SRC-003 | verified | A bounded application may deliberately apply closed-world checks, but it must declare that behavior. | Codex source check |
| CLM-021 | RDFS domain and range statements participate in semantic inference and should not be taught as equivalent to form-validation constraints. | SRC-005; SRC-004 | verified | SHACL is the primary validation language taught in this course. | Codex source check |
| CLM-022 | SHACL conformance means the data graph satisfies the declared shapes for that validation run. | SRC-004 | verified | Conformance does not establish real-world truth, completeness, safety, or fitness for every purpose. | Codex source check |
| CLM-023 | Identity resolution requires evidence and governance beyond labels that happen to match. | DIR-004 | expert interpretation | Exact matching methods, thresholds, and authoritative sources are implementation-specific. | pending utility review |
| CLM-024 | A source system can be authoritative for one statement type or time period without being authoritative for every decision. | DIR-004; SRC-011 | expert interpretation | Authority is an organizational policy decision, not supplied by RDF or PROV-O alone. | pending governance review |
| CLM-025 | GeoSPARQL provides a standard way to represent and query geospatial linked data. | SRC-012 | proposed | Practitioner reference only until version and profile selection are reviewed. | pending technical review |
| CLM-026 | OGC SensorThings API provides an open, geospatially enabled model and API for sensor observations and tasking. | SRC-013 | verified | SensorThings is not itself an RDF standard and should be taught as an integration reference. | Codex source check |
| CLM-027 | RDF is not automatically the best solution when a stable local table, document retrieval system, time-series store, or geospatial query already meets the requirement. | DIR-004 | Hardeep Anand position | This is an architecture decision principle, not a standards claim. | pending blueprint approval |
| CLM-028 | A data model, ontology, semantic layer, and runtime AI context answer different architecture questions. | DIR-005; SRC-001 through SRC-005 | expert interpretation | The terms are used differently across products and organizations. The course must define its usage explicitly. | pending blueprint approval |
| CLM-029 | A context engine retrieves, filters, validates, and assembles a task-specific context package; it is not the package itself. | DIR-005 | Hardeep Anand position | “Context engine” is an architecture term, not a W3C standard. | pending blueprint approval |
| CLM-030 | Better context can reduce ambiguity and unsupported generation but does not make generative AI perfectly deterministic. | DIR-005; SRC-009 | supported with limitation | Outcomes depend on evidence, retrieval, assembly, model, decoding, tools, and runtime state. “Reduce hallucination” requires evaluation against a defined task. | pending AI review |
| CLM-031 | Ontology is a fundamental requirement for agentic AI. | DIR-005 | Hardeep Anand position with limitation | Explicit shared meaning is highly valuable for the targeted enterprise utility use cases, but not every agentic application requires a formal OWL ontology. Avoid stating this as a universal technical fact. | pending blueprint approval |
| CLM-032 | An ontology kept only in a presentation, glossary, or modeling file does not by itself change runtime system behavior. | DIR-005 | supported expert interpretation | Runtime value requires implementation such as mappings, query services, application logic, validation, or context assembly. | pending architecture review |
| CLM-033 | Stardog Virtual Graphs can map external structured and semi-structured data into a graph view and rewrite eligible SPARQL query parts to source-native queries. | SRC-015 | verified | Feature behavior, supported sources, pushdown, security, performance, and limitations are product- and version-specific. | Codex source check |
| CLM-034 | R2RML defines mappings from relational databases to RDF datasets. | SRC-016 | verified | It does not define a complete enterprise semantic platform or every semi-structured mapping. | Codex source check |
| CLM-035 | Databricks query federation can query supported external databases without first ingesting the data into Databricks. | SRC-017 | verified | Databricks documents read-only and performance limitations and recommends ingestion or materialization for some production workloads. | Codex source check |
| CLM-036 | “Virtualize before replicate” and “move the least data” are useful default decision prompts. | DIR-005 | Hardeep Anand position | They are not absolute rules. Latency, availability, security, transformation, volume, cost, audit, and recovery may justify materialization. | pending blueprint approval |
| CLM-037 | Vector indexes and embeddings can make unstructured content retrievable for AI applications. | SRC-009; DIR-005 | supported with limitation | Similarity retrieval does not establish explicit identity, ontology alignment, authority, or truth. | pending AI review |
| CLM-038 | Eighty percent of enterprise data is unstructured. | DIR-005 | unresolved | No source, population, measurement method, or time period is supplied. Do not use the percentage in instruction. | pending research |
