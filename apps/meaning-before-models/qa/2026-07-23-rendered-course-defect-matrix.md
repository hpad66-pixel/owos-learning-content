# Meaning Before Models Rendered Course Defect Matrix

Date: 2026-07-23

Status: Open remediation

## Release decision

The 0.8.0 live-review candidate does not satisfy the OWOS Course Production Contract in rendered
use. Static conformance passed, but the rendered learner experience was not a completed release
gate. The current candidate must be replaced.

## Course-wide defects

| Area | Observed evidence | Contract impact | Required correction |
| --- | --- | --- | --- |
| Repeated structure | Modules 01 to 04 and 06 to 18 share the same five-section teaching body, opening shell, mechanism laboratory, artifact form, and conclusion pattern. | A different title or color is not a different learning experience. | Give every module a named narrative architecture, a distinct rendered fingerprint, and a lesson-specific sequence of visuals, interactions, and checks. |
| Flip-card presentation | Four large navy rectangles dominate every lesson. The card face has no obvious reveal affordance and reads as a dark slab. | Visual design and component clarity fail working review. | Use light question surfaces, a visible reveal instruction, stable front and answer states, focus treatment, and a reduced-motion equivalent. |
| Flip-card QA | The browser test counted the `.turned` class immediately after a click. It did not wait for or inspect the final answer face. | The test could pass when the learner-visible result was missing or obscured. | Assert final answer visibility, readable text, stable geometry, keyboard activation, and reduced-motion behavior. |
| Generic card answers | Generated answers repeat the module mental-model sentence and prepend an unrelated process step. | Recall practice does not teach the actual term or utility distinction. | Author four real question-and-answer pairs per lesson. |
| Generic graphics | Visual labels are assembled by indexing generic term and step arrays. Module 02 renders `IRI -> literal -> label`, which is not an RDF triple anatomy. | Graphics can be visually different while instructionally wrong. | Give every visual a lesson-specific title, labels, reading guide, interaction, and conclusion. |
| Generic instructor copy | Every visual repeats the same two instructor paragraphs regardless of what the learner sees. | The interface is not actually taught in context. | Author visual-specific instructions that explain where to look, what to do, what changes, and what the utility conclusion is. |
| Non-purposeful visual controls | Visual buttons only toggle an `.active` class. They do not reveal evidence, cause, sequence, or a result. | Claimed interactivity is decorative. | Every interactive visual must update an explanatory result or simulation state. |
| Repeated mechanism lab | Every lesson uses the same four-button inspection pattern and the same generic result sentence. | Adjacent modules repeat the same interaction pair. | Use lesson-specific interaction families such as path tracing, assembly, comparison, decision branching, validation, and state transition. |
| Quiz correctness | Some classify answers are generated by list position, matching pairs are mislabeled when shuffled, and estimate checks pass without comparing an answer. | Deterministic assessment is not trustworthy. | Store explicit answer specifications, explanatory feedback, and retry behavior for every scored check. |
| False QA confidence | Quality reports accurately listed rendered browser, device, keyboard, screen-reader, and practitioner checks as outstanding, but the course was published and later described as fully passing. | A blocked hard gate was overridden by static checks. | Publish a machine-readable rendered QA receipt and prevent release when required checks are missing, stale, or failed. |

## Module-by-module review requirement

Each of the eighteen module reports must be regenerated after remediation with:

1. its narrative architecture and rendered fingerprint;
2. four lesson-specific graphics and their instructional jobs;
3. two functioning interactions or simulations;
4. three varied, correctly scored quiz types plus the applied assessment;
5. flip-card final-state evidence;
6. desktop and phone screenshots;
7. keyboard, focus, reduced-motion, overflow, contrast, and console results;
8. unresolved factual, practitioner, learner, and screen-reader reviews kept visible; and
9. a release decision that cannot be inferred from the numeric score alone.
