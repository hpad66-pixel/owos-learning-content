# Module 17 Design Brief: BI, RAG, Graph Retrieval, and Context Engines

Status: approved for production under standing owner authorization

## Learning decision

The learner must compare four end-to-end answer paths, identify fixed, configurable,
probabilistic, external, and unknown stages, and defend an evidence and repeatability plan.

## Experience architecture

This is a synchronized pipeline laboratory. Business Intelligence, document Retrieval-Augmented
Generation, graph retrieval, and a context engine answer the same upstream-overflow question. The
learner reruns each path, changes one stage, and observes whether evidence, selection, wording, or
action state changes.

## Signature mechanisms

The Synchronized Answer-Pipeline Laboratory selects the appropriate path for five utility questions.
The Repeatability Microscope identifies which stage caused changed rows, retrieved passages,
bindings, context, wording, or blocked states.

## Work product

The Answer Repeatability Map records the question, selected pipeline, source snapshot, mappings,
query or retrieval configuration, inference and validation settings, context contract, generation
settings, evidence receipt, repeatability test, evaluation, owner, and use boundary.

## Evidence boundary

Repeatability belongs to a configured end-to-end pipeline. Tables, graphs, Retrieval-Augmented
Generation, and context engines can each contain fixed, variable, unavailable, and externally
changing stages.
