Clinic intake

A plausible record can still break the contract

Pump P-104 appears in the asset graph with a label, station, and status. It looks reasonable to a person. Yet the record has no durable asset identifier and its rated flow has no unit. A downstream agent can retrieve the number but cannot safely interpret it.

SHACL, pronounced "shackle," lets a team describe testable expectations for RDF data. A shapes graph declares what to check. A validation engine evaluates a data graph and produces a results graph.

02
Diagnostic report

A useful failure points to the exact place

A SHACL result should not merely say bad data. It identifies the focus node being checked, the result path, the constraint component, severity, source shape, and a human-readable message.

That precision turns validation into a governed workflow. A steward can repair the value, route an exception, or challenge the shape itself.

04
Repair and rerun

Validation belongs in a repeatable lifecycle

Shapes should be versioned, tested, reviewed, and released like other executable controls. Run them at ingestion, transformation, publication, or before an agent receives context, based on risk and latency.

Treat warning, information, and violation severities according to local policy. Severity labels do not create the policy by themselves.

05
Truth boundary

Conforms is not the same as true

A record can conform and still describe the wrong pump. A required inspection date can be present yet fabricated. A shape can omit a safety-critical requirement. Conformance means the evaluated graph satisfied the declared shapes under that validation run.

Use validation alongside provenance, authority, reconciliation, sensor quality controls, and practitioner review.

Questions people actually ask

Is SHACL the same as a database schema?

Both can enforce structure, but SHACL validates RDF graphs using shapes and graph paths. It can sit across mapped and federated data rather than belonging to one table.

Does SHACL correct data automatically?

SHACL reports conformance results. A separate governed process may repair data or route exceptions.

Can a conforming record still be wrong?

Yes. A value may satisfy datatype and range constraints while misrepresenting reality. Provenance and verification are separate.

Should every warning block an agent?

Not automatically. Your policy maps result severity and use case risk to continue, hold, review, or reject.

Who owns a shape?

A domain owner should own its business meaning while data stewards and platform teams help implement and test it.

Evidence boundary

SHACL evaluates an RDF data graph against declared shapes. Conformance is relative to those shapes and does not establish truth, completeness, safety, or universal fitness.

Module Glossary

SHACL

A W3C language for describing and validating conditions over RDF graphs.

shape

A set of declared validation targets and constraints.

focus node

The graph node being validated.

result path

The property path associated with a validation result.

constraint component

The kind of validation rule that produced a result.

conformance

The outcome that a data graph satisfies the evaluated shapes under a validation run.

results graph

The RDF graph containing the validation report and individual results.
