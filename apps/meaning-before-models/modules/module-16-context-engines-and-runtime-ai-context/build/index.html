01
Two-shift opening

The same words can describe two different tasks

At 08:00 a planner asks, 'What should we do about Overflow 21?' The planner needs causes, similar events, candidate work, and budget options. At 22:00 an operator asks the same words during an active event. The operator needs current telemetry, location, permit requirements, workflow state, permissions, and an escalation route.

Ontology definitions remain durable across both requests. Runtime context changes with user intent, identified entities, time, jurisdiction, role, state, and permitted action.

02
Assembly process

A context engine assembles the packet; it is not the packet

A context engine interprets intent, resolves identity, retrieves evidence, filters permissions, checks freshness, reconciles conflict, validates required elements, and assembles a response schema and tool boundary.

The runtime AI context is the resulting task package. Record where each element came from and why it was included or denied.

03
Runtime Context Assembly Console

Assemble only what this task needs now

Read each element and decide whether it is Required, Optional, Prohibited, Stale, or Unresolved for the active overflow response. More context is not always better. Least privilege and task relevance reduce unnecessary exposure.

Correct every item before the packet can proceed. A missing permission or unresolved event identity must block action even when the model can write a fluent answer.

04
Context provenance fan

Every element needs a source and state receipt

The event identity may come from incident management. Telemetry comes from operational technology with observation time. The permit clause comes from an approved document version. User permissions come from identity and access management. Workflow state comes from the incident process.

A useful receipt records source, locator, version, observation or effective time, review state, authority scope, access decision, and transformation.

05
Fail-closed gate

Fluent recommendation is still before approval and action

Separate retrieve, analyze, recommend, draft, approve, and act. Each transition can have a different permission. A context engine should withhold tools or return a hold state when required evidence, policy, freshness, or authorization is missing.

Choose the earliest gate that prevents the unsafe transition. Do not let generated prose silently cross from suggestion into operational action.

Professional application

Make the runtime packet testable before connecting tools

Choose one bounded task and define exactly what must, may, and must not enter context. Name freshness rules, conflict behavior, tool permissions, output schema, and stop conditions.

Include tests for a complete packet, stale evidence, denied content, conflicting authority, missing permission, and unavailable source. That is how a context contract becomes operational.

Questions people actually ask

Is an ontology the context?

No. An ontology supplies durable shared meaning. Runtime context also includes the task, entities, evidence, policy, time, permissions, workflow, and output limits.

Is a context engine just vector search?

No. Retrieval may be one step. The engine also filters, validates, reconciles, applies permissions, and assembles the task packet.

Why not send every available document?

Irrelevant or unauthorized content increases exposure, conflict, cost, and ambiguity. Send the bounded evidence needed for the task.

Does better context stop hallucination?

It can reduce ambiguity and provide evidence, but it cannot guarantee complete or correct generation.

Why include workflow state?

The same evidence may permit analysis, a draft, an approval request, or an action depending on the current state.

Should context change by user role?

Yes, when permissions, detail, tools, or allowed actions differ. The underlying facts should remain evidence-based.

Evidence boundary

Runtime context is a task-specific package assembled from governed sources and state. Better context may improve consistency but does not guarantee correctness or deterministic generation.

Module Glossary

AI context

The task-specific package supplied to a model or agent at runtime.

context engine

A service that retrieves, filters, validates, reconciles, and assembles runtime context.

least privilege

Providing only the data and capabilities required for an authorized task.

workflow state

The current approved stage and permitted transitions in a process.

fail closed

Blocking or holding when required evidence, policy, or permission is missing.

output schema

A declared structure and constraint for the model response.
