# Module 20 Phase 0 Reconciliation

## Governing identity

- Course: Meaning Before Models
- Module: 20 of 20
- Title: One Water Knowledge Spine Lab: From Utility Question to Governed Action
- Role: Applied simulation and transfer laboratory
- Required prior learning: Modules 1 through 19
- Design state: Ready for owner review
- Implementation state: Not started

## Why Module 20 exists

Module 19 answers whether a bounded Knowledge Spine pilot is worth building. Module 20 answers what the complete governed pattern looks and feels like when it runs.

The laboratory solves the abstraction problem by making the entire sequence visible:

```text
utility question
-> identities
-> triples
-> graph
-> query
-> validation
-> inference boundary
-> evidence
-> runtime context
-> authorization
-> action
-> verification
-> audit
-> adaptation
```

Module 20 does not replace the capstone. It consumes the approved Module 19 Pilot Canvas and makes the learner prove that the design can survive a realistic rehearsal.

## Prerequisite handoff

The Module 19 work product is accepted only when:

- the operational question is bounded;
- the Graph Fit Test justifies a graph;
- the decision owner and permitted action are named;
- the evidence strategy is attributable and time-aware;
- inference and validation boundaries are explicit;
- the Module 18 Agent Action Contract is accepted;
- security, authority, success, stop, and scale gates are visible;
- the recommendation is build or revise-with-defined-corrections.

A Module 19 stop decision remains valid. In that case, the learner uses Module 20 to demonstrate why a simpler architecture is the better choice.

## Adjacent-module distinctiveness

| Module | Dominant job | Signature experience |

| 18 | Control one proposed action | Authorization control room |
| 19 | Decide whether to fund a bounded pilot | Cross-functional Pilot Review Board |
| 20 | Rehearse and adapt the complete system | Full-screen build, run, break, repair, and transfer laboratory |

Module 20 must not become another lecture, canvas, review board, generic form, or static architecture page.

## Evidence and safety boundaries

- Every utility record, event, identifier, metric, and tool execution is fictional or simulated unless separately cited.
- The laboratory runs entirely in the course HTML and does not connect to production systems.
- Simulated writeback never creates a real work order.
- A successful graph query does not prove real-world truth.
- A valid SHACL result does not prove evidence accuracy.
- An inference does not create operational judgment or authority.
- A grounded recommendation does not grant permission to act.
- The custom-use-case mode stores only learner-entered instructional configuration within the governed course boundary.
- Exported configuration is a planning artifact, not executable production authorization.

## Phase 0 exit test

Phase 0 is complete when the twenty-module sequence is recorded, Module 19 has a testable handoff, the laboratory has one complete simulation chain, water-wastewater-stormwater transfer is defined, the custom-use-case path is bounded, and no implementation has begun.
