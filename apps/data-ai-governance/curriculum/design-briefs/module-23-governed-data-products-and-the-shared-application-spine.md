# OWOS Module Design Brief

## Identity

| Field | Decision |
| --- | --- |
| Course and module ID | `owos-master-data-governance-001`, `dga001:23` |
| Working title | A reusable dataset is not yet a product |
| Archetype | Product design studio |
| Controlled sources | Method v2.3 Chapters 9 and 10; syllabus Chapter 23 |
| Evidence boundary | No architecture, access, capital, operational, or production-release authority |

## Learning job

The learner defines a governed network-risk product, separates owner roles, maps consumers to a shared application spine, gates release, and produces a data-product contract and evidence pack.

## Concept-to-experience plan

| Teaching idea | Visual | Learner action | Assessment |
| --- | --- | --- | --- |
| Product accountability is layered | `layered-stack` | Read purpose through lifecycle | `product-or-dataset-classification` |
| Shared records serve bounded applications | `network-diagram` | Switch consumer applications | `connector-evidence-review` |
| Release requires critical evidence | `phase-gate` | Toggle release gates | `usefulness-release-judgment` |

## Module design fingerprint

- Signature mechanism: design a data-product contract and shared application spine.
- Opening: reusable data has no service accountability.
- Narrative: contract, classify, map reuse, inspect connector, gate release, judge expansion.
- Purposeful interactions: application-spine consumer mapping and data-product release gate.
- Visual sequence: `layered-stack`, `network-diagram`, `phase-gate`.
- Quiz sequence: `product-or-dataset-classification`, `connector-evidence-review`, `usefulness-release-judgment`, final product defense.
- Work-product mode: governed data-product contract.
- FAQ: six product-team questions.

## Instructor explanation plan

The contract-stack explanation links user value to meaning, evidence, service, control, and lifecycle. The spine explanation shows shared records with bounded views. The release explanation makes missing proof and critical holds visible. Assessment explanations distinguish a product from a file and use from justified usefulness.

## Visual pacing review

The lesson alternates product definitions, a worked network-risk case, three explanatory visuals, three assessments, role views, and the contract studio. Mobile stacks the spine interface and maintains labeled gates. Reduced motion retains every state.

## Learner FAQ plan

Questions address APIs, virtualization versus copying, product ownership, agent access, adoption versus usefulness, and retirement.

## Recording script

Not planned. Written teaching and interactions are sufficient.

## Diversity check

Chapter 22 is time-boxed mobilization. Chapter 23 is a product contract and shared-record network. Chapter 24 becomes a scale hearing. Its visual, quiz, interaction, and artifact fingerprints are unique.
