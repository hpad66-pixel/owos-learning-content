# OWOS Module Design Brief

## Identity

| Field | Decision |
| --- | --- |
| Course and module ID | `owos-master-data-governance-001`, `dga001:18` |
| Working title | A convincing demo can still be unfit |
| Learner roles | Utility staff, AI product owners, data and model teams, risk reviewers, leaders |
| Competencies | Gate an AI use across purpose, data, model, context, action, and monitoring |
| Controlled sources | D11 course research; NIST AI RMF; NIST Privacy Framework; ISO/IEC 42001 overview |
| Evidence boundary | No model validation, data-use authority, ethical determination, or operational release |

## Learning job

The learner must challenge a high-accuracy sewer model whose labels, rights, runtime context, and action boundary are not governed, then create a use-specific contract.

## Instructor explanation plan

| Component | Instructor job | Debrief |
| --- | --- | --- |
| AI risk heat grid | Explain that the whole use is governed | Accuracy does not cure rights or action failures |
| AI release gates | Walk purpose through action in order | Approval belongs to one versioned use |
| Release check | Distinguish metric evidence from release authority | Human review is not a universal control |

## Visual pacing review

- Five numbered runway gates provide a chapter-specific page rhythm.
- The worked leakage example interrupts abstract AI terminology.
- A context packet grounds runtime context in utility workflow.
- Mobile presentation collapses the numbered runway and boards; reduced motion keeps instant state changes.
