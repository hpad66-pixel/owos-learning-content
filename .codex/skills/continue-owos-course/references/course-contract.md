# OWOS Course Contract

## Authoritative homes

| Material | Authority |
| --- | --- |
| Course research, blueprint, lessons, assessments, and release source | `owos-learning-content/apps/<course>/` |
| Shared course components and standards | `owos-learning-content/core/` |
| Hardeep's approved voice and author boundaries | `hardeep-soul/SOUL.md` and `hardeep-soul/authoring/AUTHORING_STANDARD.md` |
| Production application and learner delivery | `onewater-os-platform` |
| Learner, enrollment, progress, and transactional records | Supabase |
| Approved concepts, sources, claims, and relationships | GraphDB |
| Version history and release evidence | GitHub |

## Course workspace

Every active course maintains:

- `AGENTS.md`: durable Codex instructions;
- `COURSE-BRIEF.md`: stable promise, audience, and intended value;
- `STATE.md`: current phase, completed work, open decisions, and next action;
- `APPROVALS.md`: Hardeep's material approvals and rejections;
- `inbox/`: new unprocessed material;
- `conversations/`: preserved dictated and typed direction;
- `research/`: originals, annotations, sources, claims, and evidence boundaries;
- `author-input/`: approved Hardeep positions, examples, and transcripts;
- `curriculum/`, `assessments/`, `assets/`, and `work-products/`: governed learning source;
- `release/`: generated release evidence.

## Definition of done

A release must trace every lesson to the approved blueprint, source register, claims boundaries, golden lesson, stable IDs, quality contract, checksum manifest, Git commit, OWOS intake receipt, and production verification.

The quality gate supports judgment. It does not replace source review, learning-design review, utility-practice review, mobile inspection, accessibility inspection, or Hardeep's release approval.
